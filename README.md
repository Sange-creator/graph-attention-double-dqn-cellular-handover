# Graph-Attention Double-DQN for Cellular Handover: A Paired Simulation Evaluation

Research code and manuscript by Saange Tamang and Sulav Kandel, Paschimanchal Campus, Institute of Engineering, Tribhuvan University, Pokhara, Nepal. The manuscript was prepared for the 19th IOE Graduate Conference, 2026.

[Read the paper](paper/article.pdf) | [Paper source](paper/) | [Architecture](docs/ARCHITECTURE.md) | [Data and reproducibility](docs/DATA_AND_REPRODUCIBILITY.md)

## What this project does

This project studies how a moving phone can choose its serving cell while balancing data delivery and unnecessary handovers. It compares a learned controller with a configured A3-style controller under matched simulation conditions.

The learned controller combines graph attention with a dueling Double Deep Q-Network (Double DQN). It represents 46 cells as a graph and uses 15 features per cell, including simulated signal, traffic load, movement, and recent connection history. At each decision, it selects an allowed serving cell. The Python package and command-line tool retain the name `toponet`.

The study evaluates three frozen trained policies on 639 reserved Kathmandu-area route cases and 540 Pokhara route–layout–condition groups. The Pokhara tests use real road geometry and synthetic cell layouts. A separate load-aware rule is reported as an exploratory diagnostic. The `hpcorbit/` folder provides a matched graph-free MLP comparison workflow; completed MLP results are not included.

This is simulation research. It does not establish performance on an operating cellular network or show that graph attention caused the observed differences.

## Reported results

| Evaluation | Groups | Aggregate throughput versus A3 | Handovers per hour versus A3 |
| --- | ---: | ---: | ---: |
| Reserved Kathmandu-area routes | 639 | +8.86% to +9.99% | -36.08% to -53.00% |
| Pokhara transfer scenarios | 540 | +3.66% to +3.85% | -23.68% to -47.10% |

Each range spans the three frozen policies. Throughput is total delivered data divided by total elapsed time. These are reported results from the private experiment archive, not measurements regenerated by a clean clone.

The learned policies also show fewer ping-pongs and less weak-service time, but all three have a higher proportion of short completed stays on the reserved routes. Test routes share roads with training routes. Only three training seeds were evaluated, and the observations include simulator-provided information and known-route lookahead. See [results and limitations](docs/RESULTS.md) and the paper for details.

## What is available

- Python simulator, graph-attention model, Double-DQN agent, training, replay, and analysis code.
- Reference simulation, split, and training configurations.
- Nine code-only numerical checks.
- Paper PDF, LaTeX source, references, and figures.
- A privacy-filtered highway dashboard observation extract with a data dictionary. These observations provide context only; they were not used for model training, tuning, or evaluation.
- A graph-free MLP comparison workflow and Slurm job scripts.

Route geometry, simulation cell-layout inputs, trained policies, and complete simulation case records are not included. Full training and reproduction of the reported results require these additional assets. See [data and reproducibility](docs/DATA_AND_REPRODUCIBILITY.md).

## Install

Use Python 3.11 or newer in an environment supported by PyTorch. Dependencies are declared in `pyproject.toml`: NumPy, PyTorch, and OpenPyXL. The optional `analysis` extra adds Matplotlib.

```bash
git clone https://github.com/Sange-creator/graph-attention-double-dqn-cellular-handover.git
cd graph-attention-double-dqn-cellular-handover
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[analysis]'
python -m toponet --help
```

On Windows, activate the environment with `.venv\Scripts\activate`.

## Run the code checks

From the repository root, after installation:

```bash
python -m unittest discover -s tests -p 'test_core.py' -v
```

These checks cover the model, Double DQN, handover environment, features and rewards, radio model, interval service, resource allocator, traffic, and baseline controllers. They do not require the private experiment assets and do not reproduce the paper's full evaluation.

## Training and evaluation

The command-line interface provides `smoke`, `train`, `replay`, and `analyze`. These commands require compatible local simulation inputs; replay also requires the frozen policies and case records. The `status` and `verify-files` commands require private tracking and provenance files. They are not clean-clone demonstrations.

With the required inputs available, the following starts a short pipeline check in a new output directory:

```bash
python -m toponet smoke \
  --config configs/training/reference_ho0875_seed17.json \
  --output runs/smoke-check
```

Read [configuration](docs/CONFIGURATION.md) before starting a new experiment and [the MLP workflow](hpcorbit/README.md) before using its training or cluster scripts. New runs do not replace the frozen policies or the paper's reported results.
